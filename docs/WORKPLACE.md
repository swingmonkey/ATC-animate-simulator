# 工作现场与值班制度规范（Workplace, Roster & Avatar）

> 状态：**规范（起草于 v1.7 开发期）** · 适用版本：v2.1+（Step W1 起）
> 定位：本文与 [`docs/PLAN-v2.md`](PLAN-v2.md)、[`docs/FLIGHT-LIFECYCLE.md`](FLIGHT-LIFECYCLE.md) **三文配套** ——
> PLAN 定**架构分层与玩法系统**，FLIGHT-LIFECYCLE 定**业务过程与岗位服务**，本文定**工作现场（场景层）、角色与值班制度**。
> 凡涉及"人在哪、能不能上岗、上多久、谁来接班、现场出了什么事"的争议，以本文为准。
> 规章依据层见 [`docs/CCAR-93TM-ALIGNMENT.md`](CCAR-93TM-ALIGNMENT.md) —— **CCAR-93TM-R6 规章对齐与合规边界**（第四篇配套文档）：
> 本文的席位门槛（§3）、岗位与交接（§4）、疲劳与休息（§5）、应急与记录（§7）在该文中逐条给出**条号、偏离程度与代码落点**；两边参数必须互指、不得各写一套。
>
> **免责声明**：文中房间尺寸、席位数量、值班与休息时长、疲劳阈值、特情清单均为**示意数据**，仅用于模拟演示，
> **不得作为真实运行依据**。各管制单位的现场布局与值班制度差异很大（扇区划分方式、是否设领班、休息时长、
> 是否允许单人值守、设备型号），本项目取**典型简化**，差异项集中在数据层（`data/workspaces.js`）便于调整。

## 1. 目标与定位

**一句话**：把"三张地图"从**三个雷达屏**升级为**三个工作现场** —— 玩家不再是一个"永久在线、不会累的席位"，
而是**一个有班表、有身体、会累的人**：走进大厅，坐到自己的扇区席位上干活；干到该休息时离席，
把扇区交给接班的同事；中途还要应付现场冒出来的各种麻烦。

### 1.1 三层视图模型（本文的核心结构）

```
第 3 层  现场层（Scene）  ← 本文新增：人在哪、现场发生了什么（2D 俯视）
            │  走到席位 → 坐下 → 接管
第 2 层  席位层（Seat）   ← v1.7 已就位：三张席位地图（ACC/APP/TWR 档案 + 图层集 + 独立视口）
            │  点飞机 → 下指令 → 看反馈
第 1 层  信息层（Info）   ← 已交付：HUD / 进程单 / 指令台 / 通话面板 / 结算
```

| 层 | 回答的问题 | 时间尺度 | 交互手段 | 本项目现状 |
|---|---|---|---|---|
| **现场层** | 我在哪？谁在岗？现场出了什么事？ | 分钟–小时（值班） | 移动、就座、离席、交接、通报 | 待建（本文 §10 Step W1） |
| **席位层** | 我负责哪块空域/跑道？看得见什么？ | 秒–分钟（指挥） | 点击/框选、缩放、图层开关 | 档案与多视图几何已就位，**渲染接线待做** |
| **信息层** | 现在该做什么？做得怎么样？ | 实时 | 指令台、进程单、HUD、结算 | 已交付（v1.5 / v1.6） |

**关键约定**：三层**不是三个独立小游戏**。现场层只负责"入场 / 退场 / 换岗 / 突发"这一段；
**一旦就座，画面与操作与现在完全一致**（席位层 + 信息层）。现场层**包裹**席位层，永不替代它。

### 1.2 范围

- 覆盖：3 个现场（**区域管制大厅 / 进近管制室 / 塔台**）的俯视布局、席位构成、可接管岗位、移动与就座
- 覆盖：**值班制度**（工作时段 / 疲劳 / 强制休息 / 交接班 / 离席代管）、**领班巡视**、**突发情况系统**
- 覆盖：与既有 6 个岗位（`CD/APC/GND/TWR/APP/ACC`，见 FLIGHT-LIFECYCLE §2）以及三张席位地图档案的映射
- 不覆盖：3D 建模与人物美术（本项目是 Canvas 2D，小人用**俯视符号 + 朝向 + 名字牌**表达）、真实排班规章、真实编制与设备型号

### 1.3 三条设计红线

| 红线 | 含义 | 反面（必须避免） |
|---|---|---|
| **移动必须低成本** | 默认就坐在席位上；提供"快速前往"；不为走路而走路 | 做成步行模拟器，玩家 80% 时间耗在走廊上 |
| **离席不能毁体验** | 离席/休息期间由 AI 同事**代管**，游戏继续且可控 | 休息 15 分钟回来发现全场乱套、无法挽回 |
| **一切可复现** | 疲劳、AI 代管决策、突发事件触发全部走 `core/random.js` 种子 | 现场层引入不可复现的随机，毁掉复盘与评分的依据 |

## 2. 三种工作现场（俯视布局）

三个现场**对应三张席位地图**，但现场是"房间与人"，席位地图是"屏幕里的图"。
下图为**示意布局**（方格 ≈ 2 m），坐标与家具全部来自 `data/workspaces.js`，可改数据而不改代码。

### 2.1 区域管制大厅（ACC 现场）

|---|---|---|---|---|

（叠加一层简化目视视图：跑道延长线 + 五边上的航空器符号），这是"塔台为什么是目视岗位"的最小表达。

### 2.4 现场之间的移动与"接班"

| 方式 | 触发 | 耗时（示意） | 说明 |
|---|---|---|---|
| 步行 | `WASD` 走到 `DOOR`，再走到目标现场 | 走道 15 s + 换现场 20 s | 默认方式，有"经过走廊"的过场（黑屏 + 文字） |
| 快速前往 | `F` 打开现场地图，点目标席位 | 30 s（模拟时刻） | **推荐方式**，避免把时间耗在路上 |
| 接班抵达 | 值班表到期（§5.4） | 0 | 接班管制员 AI 自动"到场"，玩家只需完成交接 |

> **确定性要求**：所有"耗时"都推进**模拟时钟**（`state.time`），不消耗真实等待；快进倍率下同样成立。

## 3. 现场 × 席位 × 视图映射

**一句话**：**现场座位 → 岗位代码 → 席位地图档案**，三者用一张表钉死，避免"坐到哪个位置看到哪张图"靠猜。

| 现场 | 席位 id | 岗位代码 | 席位地图档案 | 在管范围 | 需坐席才能指挥 | 数据来源 |
|---|---|---|---|---|---|---|
| 区域管制大厅 | `ACC-01` | `ACC` | `ACC`（220 km，FL 高度层） | 全域 | ✅ | `data/workspaces.js` + `data/viewProfiles.js` |
| 区域管制大厅 | `COORD` | `ACC` | —（无地图，**通报板 + 协调对话框**） | — | ✅ | 同上 |
| 进近管制室 | `APP-ARR` | `APP` | `APP`（65 km，MVA + 程序） | ≤ 60 km | ✅ | 同上 |
| 进近管制室 | `APP-DEP` | `APP` | `APP`（同档案，图层切"离场"） | ≤ 60 km | ✅ | 同上 |
| 塔台 | `TWR` | `TWR` | `TWR`（15 km，跑道/五边/塔台圈） | ≤ 15 km | ✅ | 同上 |
| 塔台 | `GND` | `GND` | `GND`（3–5 km 地面图，**v1.8 新建**） | ≤ 5 km + 地面 | ✅ | 同上 |
| 塔台 | `CD` | `CD` | **无地图**（进程单 + 放行许可核对表） | — | ✅ | 同上 |
| 塔台 | `APC` | `APC` | `APC`（1–2 km 机坪图，可与 `GND` 合并） | 机坪 | ✅ | 同上 |

**三条规则**

1. **一席一图**：坐到席位 = 把该席位的档案（视口 + 图层集）应用到主画布；离开席位 = 回到现场层俯视图。
2. **不在岗不可指挥**：不在席位上时，点击飞机**不产生指令**，只能看（防止"人还在走廊上却能指挥"的逻辑漏洞）。
3. **合并规则数据化**：中小机场把 `CD/APC/GND` 合并进 `TWR` 席位（`data/workspaces.js` 的 `merge: ['CD','APC','GND']`），
   现场图上只画一个"塔台/地面"席位——**同一份代码，两种机场规模**。

## 4. 角色模型

### 4.1 三类角色

| 类型 | 数量（示意） | 由谁控制 | 行为来源 | 例子 |
|---|---|---|---|---|
| **玩家小人（Avatar）** | 1 | 玩家（`WASD` / 点击 / 快速前往） | `interaction/avatarInput.js` | 你 |
| **AI 同事（Colleague）** | 2–5 | AI | `game/workplace.js` 的确定性规则 + 种子随机 | 邻扇区管制员、协调席、放行席 |
| **领班（Supervisor）** | 1 | AI | 巡视路径 + 检查项（§6） | 巡视中、通报、授权 |

### 4.2 玩家小人的状态机

```
        ┌────────┐  走到席位    ┌──────────┐  按 E 就座   ┌──────────────┐
        │ IDLE   │ ───────────► │ WALKING  │ ───────────► │ SEATED       │
        │(站立)  │ ◄─────────── │ (移动中) │              │ (在席位/图上) │
        └────┬───┘   按 Q 起身   └──────────┘              └──────┬───────┘
             │                                                    │
             │  走到 REST / PANTRY                     疲劳 ≥ 阈值 │  交接完成
             ▼                                                    ▼
        ┌──────────┐  休息计时结束  ┌──────────┐  走到 HANDOVER  ┌──────────────┐
        │ RESTING  │ ────────────► │ IDLE     │ ─────────────► │ HANDOVER     │
        │ (休息中) │                │          │                │ (交接单流程) │
        └──────────┘                └──────────┘                └──────────────┘
```

| 状态 | 含义 | 可否指挥 | 疲劳 | 备注 |
|---|---|---|---|---|
| `IDLE` | 站在现场某处 | ❌ | 缓慢恢复 | 默认出生点在**自己席位上**（`SEATED`），避免开局先走路 |
| `WALKING` | 沿通道移动 | ❌ | 缓慢恢复 | 路径用 `data/workspaces.js` 的通道节点图（直线 + 拐点） |
| `SEATED` | 坐在席位（= 现在的主玩法） | ✅ | 累积 | 座位决定"用哪张地图" |
| `RESTING` | 在休息区 | ❌（**AI 代管你的席位**） | 快速恢复 | 强制休息见 §5.3 |
| `HANDOVER` | 在交接台做交接 | ❌ | 冻结 | 检查单见 §5.4 |

### 4.3 AI 同事的行为（保持"可复现"）

AI 同事只做**三件事**，且都是**确定性规则 + 种子随机**，不做寻路 AI：

| 行为 | 规则 | 玩家感知 |
|---|---|---|
| **代管你的席位** | 你离席时接管：按"最省事策略"处理（保持航向/高度、按程序移交、必要时复飞） | 通话面板出现 `[代管]` 前缀的播报；效率分下滑 |
| **邻扇区工作** | 不模拟其指挥细节，只按负载给出**状态**（空闲/正常/繁忙/超载） | 席位牌显示状态色；超载时领班会来协调 |
| **走动** | 按班表在席位/休息区/交接台之间移动（时间化，不寻路） | 现场层能看到同事在走动、交接班时有人过来坐下 |

> **红线**：AI 代管**必须走 `core/random.js`**（同一 seed 同一结果），否则复盘与评分不可信。

## 5. 值班制度（Roster）

### 5.1 时间尺度：短班 vs 整班

| 模式 | 时长 | 用途 | 现状 |
|---|---|---|---|
| **短班** | 15–25 min（现状 v1.5–v1.6） | 单次演练，一坐到席位上就开干 | ✅ 已交付 |
| **整班** | 一个值班周期（示意 90 min 工作 + 15 min 休息，可配多轮） | 完整体验"上岗 → 疲劳 → 休息 → 交接" | 本文目标态（Step W2） |

> **兼容要求**：短班模式**永远保留**（它是快速演练与关卡挑战的入口）。整班模式只是把短班**串起来**，
> 中间插入"休息 / 交接"两个环节——**不改变席位层的任何玩法**。

### 5.2 疲劳值（`fatigue` 0 → 1）

| 项 | 规则（示意） | 常量（`core/constants.js`） |
|---|---|---|
| 累积 | 在岗每秒 `+1 / WORK_SEC`；告警/特情期间额外 `+1.5×` | `WORK_SEC = 5400`（90 min） |
| 恢复 | 休息区每秒 `−1 / REST_SEC`（比累积快 8 倍） | `REST_SEC = 900`（15 min） |
| 阈值 | `0.6` 提示休息；`0.85` **强制休息**（领班口头要求） | `FATIGUE_WARN = 0.6` / `FATIGUE_FORCE = 0.85` |

**疲劳的游戏化影响**（必须可复现、必须"可感知但不致命"）：

| 影响 | 疲劳 < 0.6 | 0.6 ≤ 疲劳 < 0.85 | ≥ 0.85 |
|---|---|---|---|
| 复诵错诵率 | 基准（难度设定） | ×1.5 | ×2.5 |
| 指令台推荐用语 | 全部显示 | 仅显示**高频**用语 | 仅显示**核心**用语（高度/进近/落地） |
| 告警响应时限 | 基准 | ×0.8 | ×0.6 |
| 画面 | 正常 | 边缘轻微暗角 | 暗角 + 时钟偶发"走神"提示（0.5 s 提示延迟） |

> 疲劳**不降低**飞机的机动性能、**不制造**安全事故——它只让**你的操作更容易出错**。这是"惩罚玩家自己"而非"惩罚世界"。

### 5.3 强制休息（`REST_DUE` → `REST_IGNORED`）

1. 疲劳 ≥ `0.6`：领班**口头提醒**（通话面板 + 现场层领班走近），HUD 出现"建议休息"角标
2. 疲劳 ≥ `0.85`：**强制休息**——领班要求你离席，**30 s 宽限**（`REST_GRACE_SEC = 30`）
3. 宽限内离席：正常，交接流程自动启动（§5.4），无扣分
4. 超时未离席：每次记 `REST_IGNORED`（−4），并**强制**插入"疲劳错诵"（下一次定向指令必错诵一项）

### 5.4 交接班（Handover）

**触发**：① 值班周期结束（接班管制员到场）；② 强制休息；③ 玩家主动离席（可选"简单交接"）。

**交接检查单（7 项，逐项确认）** —— 这是"把扇区交出去"的仪式，也是评分点：

| # | 检查项 | 内容来源 | 漏项后果 |
|---|---|---|---|
| 1 | **扇区态势** | 当前在管航班数与分布 | `HANDOVER_MISSED` −2 |
| 2 | **活动航班** | 已发进近许可 / 已进跑道 / 五边上的航班 | 同上（+1 项权重 ×1.5） |
| 3 | **等待/排序** | 等待航线、排序序列、复飞航班 | 同上 |
| 4 | **流控与限制** | 通报板上的流控、高度限制、临时空域 | 同上 |
| 5 | **天气与跑道** | 风、跑道构型、正在切换的跑道 | 同上 |
| 6 | **特情** | 未处置完的特情与已采取的处置 | 同上（+1 项权重 ×2） |
| 7 | **设备状态** | 雷达/通信/进程单系统是否降级 | 同上 |

**交接质量评分**：

```
交接得分 = 7 项检查单：全对 +6 / 每漏一项 −2（特情漏项 −4）
          交接耗时 ≤ 120 s 额外 +2；> 300 s 记效率 −1
```

**接班管制员（AI）**：交接完成后**由 AI 接管该席位**，接管质量按"你交接的完整度"决定——
漏报"五边上有飞机"→ AI 接手后可能让飞机复飞（并在复盘时间轴上标出**是你的交接漏项导致的**）。
这让"交接"有真实后果，而**不是**一段过场动画。

### 5.5 离席与"空岗"

| 情形 | 规则 | 评分事件 |
|---|---|---|
| 已交接后离席 | 合法；AI 代管 | — |
| **未交接**离席 | 允许但危险：席位进入 `UNATTENDED`，AI 用"最保守策略"代管（一律保持，不主动排序） | `SEAT_UNATTENDED` −3 / 每次告警 |
| 离席期间告警 | 通话面板以 `[代管]` 前缀播报；玩家可通过"通话面板"远程接管（W2 可选） | 效率分下滑 |

### 5.6 值班参数一览（示意，全部可调）

| 参数 | 示意值 | 位置 |
|---|---|---|
| 工作时长 / 休息时长 | 90 min / 15 min | `data/workspaces.js` 的 `roster` |
| 疲劳累积/恢复速率 | 见 §5.2 | `core/constants.js` |
| 交接检查单耗时 | 每项 15 s（可"一键确认"熟练项） | 同上 |
| 快速前往耗时 | 30 s（模拟时刻） | 同上 |
| 领班巡视周期 | 8 min / 圈 | `data/workspaces.js` 的 `supervisor.route` |

> **与规章硬指标的对应**：上表是"现场节奏"参数；与 §123–§128 的执勤/岗位执勤/休息口径、
> 以及 **雷达管制连续岗位执勤 ≤2 h、两次岗位执勤间隔 ≥30 min** 等硬指标的双栏对照见
> [`docs/CCAR-93TM-ALIGNMENT.md`](CCAR-93TM-ALIGNMENT.md) §8。本文的 `fatigue` 曲线必须由该文的 `data/roster.js` 参数驱动，**不另设一套**。

## 6. 领班（Supervisor）

**定位**：领班不是"又一个管制员"，而是**现场的节奏控制者** —— 他巡视、通报、授权、讲评。

### 6.1 巡视路径与检查项

```
大厅示例：SUP 席 → ACC-01 → ACC-02 → ACC-03 → 通报板 → COORD → 休息区 → 回 SUP 席   （一圈 8 min）
```

| 检查项 | 触发条件（示意） | 领班动作 | 玩家可做 |
|---|---|---|---|
| **席位超载** | 在管航班 > 席位容量（示意 8 架） | 走到席位旁提醒，建议"移交/简化" | 加速移交、申请协助 |
| **告警堆积** | 5 min 内告警 ≥ 3 次 | 通报 + 记录 | 消除告警源 |
| **进程单堆积** | 未处理进程单 > 6 张 | 提醒"先清进程单" | 处理进程单 |
| **离席超时** | 离席 > 5 min 未交接 | 追责提醒 | 立即交接 |
| **疲劳** | 疲劳 ≥ 0.6 | 提醒休息（§5.3） | 离席休息 |
| **用语抽查** | 随机（种子） | 抽一条通话点评 | 用语规范者 +1 |

### 6.2 通报（`BULLETIN`）

领班（或协调席）会发布通报，**直接改变玩法条件**：

| 通报 | 内容示例 | 玩法影响 |
|---|---|---|
| 流控 | "进港每 3 分钟一架，至 12:00" | 导演注入速率下调；延误风险上升 |
| 天气 | "本场雷雨，五边有风切变" | 跑道切换 / 复飞概率上升 |
| 跑道关闭 | "02R 关闭检查，20 min" | 跑道构型变更（复用 `[configurations]` 机制） |
| 特情通报 | "CCA1234 报告发动机故障" | 启动 §7 处置流程 |
| 设备降级 | "进程单系统故障，改用纸单" | 进程单面板降级（信息层压力↑） |

> 通报必须**写进 `game/scoring.js` 的事件时间轴**，复盘时可点回到"通报那一刻"看自己怎么应对。

### 6.3 授权（`AUTHORIZATION`）

部分高权限动作**必须经领班授权**（体现"岗位权限"而非"上帝模式"）：

| 动作 | 场景 | 未授权尝试 |
|---|---|---|
| 关闭/开放跑道 | 跑道检查、FOD | 指令台灰显 + 提示"需领班授权" |
| 特情优先处置（优先落地/直飞） | 医疗、低油量 | 同上 |
| 临时空域 / 绕飞限制 | 雷雨、军航活动 | 同上 |
| 超容量接收（放行闸门） | 大流量 | 同上 |

### 6.4 讲评（`DEBRIEF`）

班次结束（§5.1 整班）时，领班给出**讲评**：3 条亮点 + 3 条改进（全部来自事件时间轴与评分事件），
**这是"可教"支柱（PLAN §1）在现场层的落点**——讲评不空泛，每条都挂具体时刻与航班号。

## 7. 突发情况系统（让用户来化解）

**设计目标**：突发事件是"现场层存在的理由"——**没有突发，现场层就只是走路**。
> 规章依据：本规则 §32 要求应急预案覆盖**设备失效**与**人员丧失能力**两类情形、至少含六项内容；
> §34 要求处置后评估并**修订预案**；§35 要求**培训与定期演练**；§42–§43 要求**防止未经许可人员进入**与访客登记陪同。
> 六要素与本项目脚本模板的逐项映射、以及演练模式 `drill` 的设计见
> [`docs/CCAR-93TM-ALIGNMENT.md`](CCAR-93TM-ALIGNMENT.md) §9。

### 7.1 三类突发事件

| 类别 | 发生在 | 玩家感知通道 | 例子 |
|---|---|---|---|
| **席位突发**（航班特情） | 席位地图上的某架飞机 | 通话面板 + 进程单红色 + HUD 告警 | 发动机故障、医疗、低油量、通信失效 |
| **现场突发**（人与设备） | 现场层 | 现场层图标 + 领班喊话 | 设备冒烟、管制员不适、断电、门禁报警 |
| **协同突发**（跨岗位） | 席位层 + 现场层 | 通报 + 领班到场 | 跑道侵入、FOD、军航活动、通信中断 |

### 7.2 突发事件清单（示意）

| 事件 | 类别 | 触发（示意） | 玩家应做（标准处置） | 成功判据 | 评分 |
|---|---|---|---|---|---|
| `MEDICAL` 机上医疗 | 席位 | 随机 / 关卡脚本 | 优先落地 + 通报领班 + 协调救护 | 落地并移交地面 | `EMERGENCY_HANDLED +8` |
| `ENGINE_FAIL` 发动机故障 | 席位 | 关卡脚本 | 保持高度、返场/就近落地、优先落地授权 | 安全落地 | +10 / 处置错误 −12 |
| `LOW_FUEL` 低油量 | 席位 | 长时间等待未落地 | 优先排序、直飞、缩短五边 | 未进入紧急油量 | +6 |
| `RADIO_FAIL` 通信失效 | 席位 | 随机 | 按程序（保持、盲发、雷达引导至落地） | 按程序处置 | +6 |
| `BIRD_STRIKE` 鸟击 | 协同 | 起飞/进近阶段 | 检查、返场、通报 | 安全落地 | +5 |
| `RUNWAY_INCURSION` 跑道侵入 | 协同 | 地面席/机坪冲突 | **立即复飞** + 通报 + 领班到场 | 无间隔损失 | +10 / 未复飞 −15 |
| `FOD` 跑道异物 | 现场+协同 | 随机 | 关闭跑道 → 检查 → 开放（需授权 §6.3） | 时限内完成 | +5 |
| `WEATHER_ESCAPE` 雷雨绕飞 | 席位 | 天气系统（已有） | 引导绕飞、协调空域 | 无 MVA 违规 | +4 |
| `EQUIP_FAIL` 设备故障 | 现场 | 随机（种子） | 报告领班 → 切换备用（进程单降级/雷达降级） | 时限内恢复流程 | +5 / 超时 −6 |
| `COLLEAGUE_SICK` 同事不适 | 现场 | 随机 | **临时顶班**（走到邻席位接管）或呼叫领班 | 席位不空岗 | +7 |
| `POWER_OUTAGE` 断电 | 现场 | 关卡脚本（高难） | 切换应急照明/备用电源、保持通话 | 无失控航班 | +8 |
| `SUSPICIOUS` 门禁/可疑情况 | 现场 | 随机 | 报告领班（不可自行处置） | 正确上报 | +3 |

> 表内 `EQUIP_FAIL` / `COLLEAGUE_SICK` / `POWER_OUTAGE` 三类**不按单条事件处理**，而应按 §32 六段预案脚本执行
>（组织分工 → 应急接管 → 安全措施 → 管制程序 → 恢复服务 → 协调机制），见对齐文档 §9.1；
> 处置完成后统一走 §9.2 的"讲评 → 预案修订"链路，演练用 `drill` 模式（不影响运行评分）。

### 7.3 处置流程（以跑道侵入为例）

```
1. 触发：GND 席报告"有车辆进入 02L"（现场层出现侵入图标 + 通报）
2. 玩家（TWR 席）：
     ① 五边有飞机 → 立即"复飞"（指令台一键，或点击飞机）
     ② 通报领班（一键"通报"）→ 领班到场（现场层可见）
     ③ 跑道标红，`isRunwayOccupied` 为真 → 后续进跑道指令灰显
3. 化解：车辆撤离 → 领班授权"跑道开放" → 恢复放行
4. 评分：复飞及时 +10；未复飞导致间隔不足 −15；上报及时 +2
5. 复盘：时间轴出现「RUNWAY_INCURSION → 复飞 → 授权开放」三段，可点回
```

### 7.4 与既有评分体系的衔接

- 席位突情的**处置动作**沿用现有指令链路（`commands` → `domain/clearances.js` → `game/scoring.js`），不新增指令通道
- 现场突发的**处置动作**是新的"现场动作"（通报/顶班/切换设备），走 `game/workplace.js` + 新评分事件
- 所有事件都写入 `game/scoring.js` 的事件时间轴，**复盘可点回**（复用 v1.5 已交付的机制）

## 10. 实施步骤与验收（每步独立可交付）

> **前置依赖**：Step W1 需要 **v1.7 席位地图渲染接线**完成（`store.activeView` + `viewProfiles` + `viewport` 已就位，
> 但"按档案切换视口与图层"的渲染入口尚未接线）。二者可并行开发，W1 验收时一并合入。

### Step W1（v2.1）现场层最小可用：三个现场 + 走到席位就座
1. `data/workspaces.js`：三个现场布局（席位/交互点/门/通道/领班路线/值班参数）
2. `game/avatar.js`：位置/朝向/移动（时间化）+ 状态机（`IDLE/WALKING/SEATED`）
3. `render/scene.js`：俯视渲染（房间/席位牌/角色/交互点/提示气泡）
4. `interaction/avatarInput.js`：`WASD` 移动、`E` 就座、`Q` 离席、`F` 快速前往、`Tab` 切现场
5. **接线**：`seat:taken` → `setActiveViewKey(view)` → 席位层渲染；`seat:released` → 回到现场层
6. 设置项"跳过现场层"（关闭时行为与 v1.6 完全一致）

**验收**：`npm run check` 零越界；`npm run smoke` 新增 ≈10 项断言（现场装载、席位→视图映射、
就座切换档案、离席回现场、非在岗不可指挥、快速前往耗时、`Tab` 切现场、跳过现场层兼容）；
人工截图：三个现场俯视图 + 就座后的席位地图。

### Step W2（v2.2）值班制度：疲劳 / 强制休息 / 交接班 / 代管

2. `game/workplace.js`：AI 代管策略（种子随机）、接班管制员到场、`bulletin` 发布
3. `ui/rosterPanel.js`：班表 / 疲劳条 / 交接检查单（逐项确认）/ 讲评
4. 评分事件：`REST_IGNORED`、`SEAT_UNATTENDED`、`HANDOVER_MISSED`、`HANDOVER_COMPLETE`；

## 11. 风险与取舍

| 风险 | 对策 |
|---|---|
| **做成"步行模拟器"** | 红线一：默认坐席开局 + `F` 快速前往 + 设置可关闭现场层；移动只占一个班次的极小比例 |
| **双模式（现场/席位）认知负担** | 状态驱动的输入分发（§8.2）+ 提示气泡 + 不在岗点击给明确原因（不静默失败） |
| **现场层破坏确定性** | 所有移动/疲劳/AI 代管都**时间化 + 种子随机**；复盘依赖事件时间轴，不依赖逐帧位置 |
| **工作量过大（三个现场）** | **先做塔台（最小现场：4 席位 + 1 交互点）**，验证管线后把数据复制到大厅/进近室——代码零改动，只加数据 |
| **与 v1.7 席位渲染耦合** | 用 `seat:taken → setActiveViewKey` 单一接口解耦；现场层不碰图层绘制逻辑 |
| **美术资源** | 全符号化（俯视方块 + 名字牌 + 状态色），不引入贴图/3D；后续可换美术而不改逻辑 |
| **值班时长与玩家耐心** | 整班模式**可配置**（60/90/120 min 三档），允许"只玩一个值班周期"；短班模式永久保留 |

**首版明确不做**（避免范围失控）：多扇区实时协作细节、真实排班规章、3D 现场、语音、
同事个体性格与对话树。
