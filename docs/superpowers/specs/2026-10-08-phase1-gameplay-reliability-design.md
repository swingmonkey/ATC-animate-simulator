# 第一阶段游戏体验修复设计

## 目标

让沙盒和评分班次各自按预期工作；玩家的点击、拖拽与指令只影响明确选定的对象；结算与模拟时间保持可信。保留现有零构建 ES 模块、Canvas 2D、Electron 和存档格式。

## 玩家可见行为

1. 启动进入沙盒，关卡可选，时间轴可拖动。进入评分班次后锁定场景编辑；暂停只停止时间，继续允许选机、下指令、结束班次。
2. 首次拖动航路点或飞机即可完成操作，双击编辑始终有效；在画布外松开鼠标会结束拖动。
3. 不存在的呼号不会广播给其他飞机。指令失败时输入框附近显示原因，保留原文便于修正；成功时显示实际生效对象。
4. 提前结束、时限已到、达标完成分别呈现结果。未达成落地目标时，最终评级不会是 S。结算仍保留原始绩效分供复盘，经营层使用最终分和评级。
5. 游戏班次时钟单调增长。沙盒保留现有时间轴回放行为；评分与导演在高倍速下按模拟时间推进，避免漏掉短暂状态。

## 状态与数据边界

- `session.meta.kind` 是沙盒或游戏班次的判断依据；供核心层编辑锁使用的运行期布尔值由班次开始、结束动作同步维护，不写入存档。
- `isEditMode()` 同时要求暂停且无进行中的游戏班次。UI 控件状态与动作处理都遵守此规则，不能只靠 CSS 拦截鼠标。
- 指令先解析并验证目标，再执行、录入和播报。解析失败不改变飞机、通话或输入录制。
- 结算保存 `outcome`、`performanceScore`、最终 `score/grade`。胜利按原绩效评级；时限失败或主动放弃的最终分上限为 59 分。
- 游戏时间不回卷；沙盒回放仍受 `timeMax` 控制。已落地或不可见飞机不参与冲突告警。

## 验收

- 初次启动可直接选 L1，沙盒时间轴可拖；游戏班次播放中可结束，暂停后不能增删改场景。
- 首次拖拽和双击有效，重复点击不会增加事件监听器。
- 向不存在的呼号下达高度指令，受影响飞机为 0，输入保留且显示原因。
- 零落地提前结算不得获得 S；达到目标的班次按正常绩效评级。
- 自由流量班次推进到 2600 模拟秒后继续出流；落地机不再触发间隔扣分；相同种子与输入在 1×/10×/60× 的关键结果一致。
