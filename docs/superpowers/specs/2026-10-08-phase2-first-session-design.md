# 第二阶段：L1 第一局教学设计

## 目标

让首次进入 L1 的玩家在可控流量下亲自完成选机、进近许可、核对复诵、落地许可与落地结算。沿用现有指令台、评分和班次系统，不改其他关卡与自由流量的玩法。

## 班次规则

- L1 只生成时间轴指定的四架进港航班，不叠加无限流量、离港航班或随机特情。四架仍按原有时刻进入，目标保持落地四架、1500 模拟秒内完成。
- L1 开始时临时关闭自动许可，并锁住该开关；结束或重开其他班次后恢复玩家原来的自动许可设置。自动移交继续可用。
- L1 默认以 5× 播放，让第一架航班尽快进入；速度控件仍可随时由玩家调整。离开 L1 后恢复进入前的倍率。
- 进近、落地及复诵继续走现有指令和领域规则，教学提示不替玩家下达指令，也不改变评分。

## 教学卡片

- 雷达左上角 HUD 下方显示简洁卡片：落地进度、当前航班、下一步操作和必要原因。卡片不遮挡进程单；班次结束时隐藏。
- 没有航班时提示等待首架；有航班但未选中时提示点击雷达或进程单；选中航班后依次提示进近许可、核对进近复诵、落地许可、核对落地复诵、等待接地。
- 复诵核对是玩家点击“已核对复诵”的教学动作。按钮只在当前机组复诵正确或已纠正时可用；漏项时提示使用指令台重新下发。核对状态只保存在当前班次内，不写入场景存档，不阻断合法管制指令。
- 指令执行失败的原因同步出现在卡片中，成功下达后清除；通讯输入框附近的现有失败反馈保留。
- 提示根据实际航空器状态派生，能处理玩家提前下达落地许可、切换选中飞机或重开班次，不把教程步骤作为结算前置条件。

## 数据与模块边界

- 场景包新增显式配置 `trafficMode: 'scripted'`、`randomEvents: false`、`autoClearance: false`、`tutorial: 'arrival-basic'`、`initialTimeSpeed: 5`。规范化时给缺省场景填回旧行为。
- `game/director.js` 只按 `trafficMode` 决定是否注入无限流量；`game/session.js` 管理 L1 临时设置和随机事件开关。
- `game/tutorial.js` 提供当前步骤模型与复诵核对状态；`ui/tutorialPanel.js` 负责显示与按钮。指令结果经事件总线通知 UI。

## 验收

- L1 到 60 秒只出现第一架进港、零离港、零无限流量；自动许可关闭且控件锁定。L2 和自由班次保持原有自动许可与流量规则。
- 选机、进近、复诵核对、落地许可各步在卡片中按实际操作变化；失败指令显示原因并不推进步骤。
- 四架航班经玩家手动许可后可以落地并以 `completed` 结算；结束或切换班次恢复原来的自动许可与速度。
- `npm run check`、`npm run smoke` 全绿，截图中教学卡片可读且不挡雷达的主要操作区。
